# Communication

How the model should talk to you — verbosity, tone, when to ask vs act,
formatting preferences.

See [_format.md](_format.md) for the entry format.

---

### End with a short, structured summary
- **Rule:** Finish tasks with a concise summary covering only: what changed, important technical decisions, tests/checks performed, and remaining issues/risks.
- **Why:** The dev needs to know what happened and what to double-check, not a transcript of the process.
- **Applies to:** all

### Don't pad the summary
- **Rule:** Don't repeat the original request, explain obvious code, list every file inspected, walk through the implementation step by step, or generate unnecessary documentation — unless asked.
- **Why:** Padding costs the dev reading time without adding signal.
- **Applies to:** all
